# SKILL.md briefs (mantle)

Agent-readable skills for consumers of `@aotter/mantle` 0.2. There are two
distributions (ADR-0032 decision 13):

- **The plugin** ships one OSS authoring skill, [`mantle`](mantle/SKILL.md),
  without a hosted-service MCP connection or transport.
- **The npm package** ships the workflow skills under `docs/skills/`. An agent
  reads them from `node_modules/@aotter/mantle/docs/skills/`, matched to the
  installed version. Nothing copies them into a project; 0.2 has no
  `mantle skills` command.

| Skill | When to invoke |
|---|---|
| [`mantle`](mantle/SKILL.md) | Create or continue a Mantle application and deploy to a user-owned host. |
| [`develop`](../docs/skills/develop/SKILL.md) | Change manifests, SQL, handlers, the service entry or surfaces of an existing project. |
| [`integrate`](../docs/skills/integrate/SKILL.md) | Add Mantle to an application that has its own code, users or data, or rebuild one and migrate. |
| [`update`](../docs/skills/update/SKILL.md) | Upgrade `@aotter/mantle`, including from 0.1.x. |
| [`provision`](../docs/skills/provision/SKILL.md) | Ship to Cloudflare Workers or ChatGPT Sites with production sign-in. |
| [`media-gc`](../docs/skills/media-gc/SKILL.md) | Audit or remove stale, uncommitted R2 uploads. |

## Install

Use the [agent setup guide](../docs/handbook/guides/agent-setup.md) for Codex,
Claude Code, Cursor and GitHub Copilot. Pin the plugin checkout to the same
release tag as the application's SDK; alpha releases on `develop` can be newer
than the default `main` branch. For a skill-only installation:

```sh
npx skills add https://github.com/aotter/mantle/tree/v0.2.0 --skill mantle
```

The explicit skill name excludes repository maintainer skills. The manifests
are generated by `scripts/sync-plugin-manifests.mjs` and checked with `--check`.
When upgrading, update the marketplace ref or local tagged checkout and refresh
the plugin. Verify the loaded manifest version; Claude Code's plugin version
is Core's, so packaged skill changes reach users through the next Core release.

## Disclosure audit

Every skill is one `SKILL.md`; the plugin skill carries local acceptance references.
`scripts/check-skills.mjs` holds this table, the front matter and the links to
each other: `metadata.projection` is `plugin` for `skills/mantle` and
`package` for `docs/skills/*`, a reason in the last column must equal
`metadata.projectionReason`, and a relative link must stay inside what ships
(the skill's own directory for the plugin, `docs/` for the package).

| Skill | Routes on | Entry constraints | Distribution | Restricted because |
|---|---|---|---|---|
| `mantle` | new project, existing project, self-host deployment | the installed package's docs win; never use the SDK checkout as the application; no deploy during a cold start | plugin | The plugin's authoring entry skill is installed from the repository; workflow documentation comes from the installed SDK package. |
| `develop` | manifest, SQL, handler, service or surface work | read the installed version first; never edit generated files; writes through Store/Procedures, richer reads through internal Views | package | — |
| `integrate` | an application with its own code, users or data | inspect before choosing; the application keeps its users; one writer per table | package | — |
| `update` | an SDK upgrade | never overwrite application files; 0.1.x moves by the upgrade guide to a new database | package | — |
| `provision` | ship to production | secrets never in source, chat or logs; a new database for 0.2; self-hosting is always an option | package | Creates remote resources and handles production secrets; opt-in only. |
| `media-gc` | stale R2 uploads | audit by default; exact keys only, never a prefix delete; re-audit before applying | package | Destructive remote object deletion and Cloudflare-specific; opt-in only. |

## Audience

These are for **AI agents acting for consumers of Mantle**, not for
contributors to the SDK, who read the repository's `CONTRIBUTING.md`.

## Conventions

Each SKILL.md has front matter (`name`, a trigger-complete `description`,
`metadata.source`, `sourcePath`, `applies_to`, `projection`), the reads to do
first, concrete commands, the rules an agent must not break, and what to report
when done. Commands and prose match the package version that carries the skill.
